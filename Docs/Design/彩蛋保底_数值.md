## 2. 每个参数的影响范围

### 2.1 `RequiredSpins`（基础保底次数 N）

- 单位：次（普通转动）。公式：`N_eff = max(1, N - D)`；`D` = 遗物减免次数（多个遗物累加，默认 0）。
- 每次普通转动充能 `+100 / N_eff` 个百分点，充满（≥99.99%）后**下一转**强制命中彩蛋。
- **N=4 时**：无遗物 → 4 次转动充满，第 5 转触发彩蛋；遗物减 1 次（N_eff=3）→ 每次 +33.3%，3 次充满。
- 影响范围：只影响充能速度，不改彩蛋效果、不改分数、不改落点权重。
- 调整副作用：N 越小，彩蛋出现越频繁（收益节奏更快）；N 必须 ≥1（代码会把 <1 的值按 1 处理）。
- 接线状态：`UIGamePanel.prefab` 里的 `GamblingGround.easterEggConfig` **已挂载** `Assets/Resources/Data/EasterEggConfig.asset`（Lead 于 2026-10-20 接好，AB 已重建）。改这个资产会直接生效；若引用丢失，代码会 fallback 到默认 N=4 并告警一次。

### 2.2 `彩蛋.asset` 的 `ChanceWeight`（25 → 0）

- 彩蛋卡不再参与加权抽取，**只能通过保底强制落点触发**（SYS-001 MUST）。
- 影响范围：`GetWeightedRandomIndex()` 的总权重从 427 降到 **377**（两张彩蛋格权重归零），所有**普通卡**概率按约 1.13 倍等比放大，卡与卡之间的相对比例不变；彩蛋自然命中率 11.7% → 0%。
- `runtimeChanceWeight` 不落盘：资产里没有该字段的序列化数据，运行时由 `GameManager.Awake → rewardList.ResetAll() → RewardData.Reset()` 从 `ChanceWeight` 同步，因此改完资产**运行时即为 0**。
- 唯一会临时改 `runtimeChanceWeight` 的代码是遗物效果（`XiaoSanYuanEffect` 乘/除权重、`SmallBecomeBigEffect` 求和），它们在效果内成对还原/只读，不写回资产。
- 注意：`QA-004`（满格后强制落点）依赖本值为 0；改为非 0 会导致彩蛋在平时也能自然抽到，破坏保底节奏。

### 2.3 轮盘彩蛋卡位置（`Rewards[9]` / `Rewards[21]`）

- v1.2 修正：轮盘保留 **2 张彩蛋图案**（索引 9、21，指向同一 `彩蛋.asset`），保底触发时从所有彩蛋卡里**等概率随机选一张**作为落点；两张卡共用同一资产，`ChanceWeight = 0` 一处改、两张同时生效。
- **不能删条目，也不能为了「唯一性」替换其他彩蛋格**：`GamblingGround.CloneGridItems()` 要求配置条数 ≥ `SideCount*4-4`，prefab 里 `SideCount=7` → **必须 ≥24 条**；删到 23 条会 `LogError("配置数据不足")` 且**一格都不建**。为「只剩一张彩蛋卡」把索引 21 换成小王是 v1.1 的错误做法，v1.2 明令作废（MUST NOT）。
- 影响范围：轮盘格数 **24（不变）**；其余 22 格索引/排布/权重不变；2 张彩蛋卡只影响**保底落点候选**（等概率 50%/50%，见 QA-013），不参与普通权重抽取。
- 合规的调整方式：改彩蛋张数只允许**原位替换「非彩蛋格 ↔ 彩蛋」**并保持总数 24；若要真正增减轮盘格数，需美术改 prefab `SideCount` + 重排 7×7 环形布局（美术范围），并同步本表。

## 3. 不变式（改数值时不能破坏）

1. 轮盘上**至少 1 张**彩蛋卡（当前 2 张：索引 9、21），且每张 `ChanceWeight = 0`；多张时保底**等概率随机选一张**，不得为了唯一性替换/删除其他彩蛋格（v1.2）。
2. `GamblingLevel.Rewards.Count` 必须 ≥ 24（当前 24）；不要删条目，替换用原位赋值。
3. `N ≥ 1`；`N_eff = max(1, N - D) ≥ 1`。
4. 彩蛋效果权重、`CanTrigger`、分数链路不动（SYS-001 禁止修改项）。
