# 商店刷新

## 1. 基本信息

- 功能 ID：SYS-002
- 级别：L1（单条功能规则改动）
- 文档版本：1.0
- 状态：Draft
- 优先级：P1
- 关联文档：Docs/02_System/商店.md（待建）、AGENTS.md §3.1
- 负责人：执行策划（数值）+ 程序（逻辑）

## 2. 设计目的

- 解决的问题：商店刷出的遗物经常与当前构筑不匹配，玩家买不到想要的方向，产生挫败。
- 希望产生的玩家体验：每个商店阶段给玩家一次「修正方向」的机会，但不是无限刷。
- 设计目标：单局内平均 60% 的商店访问会使用这次刷新；刷新后购买率提升 15%。

## 3. 功能范围

- 本次包含：刷新按钮、次数消耗、候选遗物重抽、次数用尽置灰。
- 本次不包含：付费刷新、刷新券道具、跨商店累计次数、刷新保底。
- 前置条件：玩家在商店阶段；候选遗物已生成；抽奖券 ≥ 刷新消耗。

## 4. 需求详情

- 触发条件：玩家点击商店面板「刷新」，且本阶段剩余刷新次数 > 0。
- 输入：阶段 ID、剩余刷新次数、抽奖券数量、已拥有遗物列表。
- 处理规则：
  - [MUST] 每个商店阶段初始刷新次数为 1，进入下一阶段时重置为 1。
  - [MUST] 刷新消耗 1 张抽奖券。
  - [MUST] 刷新后重抽与当前数量相同的候选，且不包含已拥有遗物。
  - [MUST NOT] 不得修改已有遗物的价格、品质和效果。
  - [MUST NOT] 不得通过其他入口绕过次数限制。
  - [MAY] 刷新时播放 0.2s 卡片翻面动画。
- 输出：新的候选列表、次数 -1、抽奖券 -1、按钮状态更新。
- 状态变化：初始 次数=1/按钮可用 → 点击后 次数=0/扣券/列表重建 → 结束 按钮置灰。
- 数值与公式：次数上限 N=1；消耗 C=1 张券；候选数量 K=4。

## 5. 详细流程

1. 初始状态：进入商店，生成 4 个候选，次数=1，按钮可用。
2. 触发条件：点击刷新，参数校验通过。
3. 系统处理：扣 1 张券 → 次数 -1 → 重抽 4 个候选（排除已拥有）。
4. 结果反馈：卡片替换、券数与次数 UI 刷新、按钮置灰。
5. 结束条件：次数为 0 或离开商店；次数不跨阶段保留。

## 6. 边界与异常情况

- 无效输入：抽奖券 < 1 时点击刷新 → 按钮不可点，不扣券不扣次数。
- 资源不足：券不足时按钮置灰并提示「チケットが足りません」。
- 重复触发：连点刷新 → 第一次点击后按钮立刻禁用，忽略后续点击。
- 中途退出或重进：次数不跨阶段保留；重进同一阶段不返还已消耗次数。
- 其他特殊情况：可抽遗物不足 4 个时按实际数量生成，不补位不重复。

## 7. 表现与交互要求

- UI：按钮在商店右下角，沿用现有按钮样式；次数显示「刷新 1/1」。
- 动画与特效：[MAY] 卡片翻面 0.2s，无强制要求。
- 音效：沿用点击音效，不新增。
- 输入与操作反馈：点击后按钮立即置灰；不可用时 hover 提示原因。

## 8. 数据与技术约束

- 输入数据：RelicData 列表（Resources/Relics）、Global.lotteryTicket。
- 输出数据：新的候选 RelicData 列表、刷新次数状态。
- 依赖系统：RelicSystem（抽卡）、UIShopPanel（界面）、Global（状态）。
- 必须保持的不变量：候选不重复；不含已拥有遗物；抽奖券不为负。
- 禁止修改的内容：RelicData 的价格/品质字段、RelicSystem.CalculateQualityWeights。

## 9. 验收标准

- [ ] 正常流程：进入商店可刷新 1 次，刷新后候选变化且不重复
- [ ] 边界条件：券不足、连点、遗物不足 4 个三种情况均不出错
- [ ] 不影响关联系统：遗物价格/品质、抽卡概率、其他面板数值不变
