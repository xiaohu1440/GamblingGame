# 彩蛋保底

## 1. 基本信息

- 功能 ID：SYS-001
- 级别：L1（现有彩蛋系统内部的规则变更；新增 Global 状态/事件属于实施细节，不升级别）
- 文档版本：1.2（2026-10-20：保底落点改为「多张彩蛋卡随机选一张」，轮盘保留 2 张彩蛋）
- 状态：Draft
- 优先级：P1
- 关联文档：Docs/03_Gameplay/（待建）、AGENTS.md §3.1
- 负责人：执行策划（数值）+ 程序（逻辑）+美术（UI资源）

## 2. 设计目的

- 解决的问题：关卡节奏过于平均，通过增加彩蛋保底改变玩家推进游戏的节奏，让玩家情绪从平淡转为期待，同时影响玩家的战斗决策和构筑决策，。
- 希望产生的玩家体验：玩家在多次转动后期待彩蛋保底带来的收益
- 设计目标：玩家在知道下一次是彩蛋保底后改变押注逻辑，让玩家押注时可以承担更大的风险以获得更高的回报

## 3. 功能范围

- 本次包含：充能UI进度条充能、彩蛋触发、彩蛋分数获取、彩蛋触发后充能进度条归0。
- 本次不包含：彩蛋的修改和删减。
- 前置条件：游戏开始且玩家在关卡阶段。

## 4. 需求详情

- 触发条件：玩家在关卡阶段。
- 输入：当前充能百分比、基础保底次数 N、遗物次数减免 D、转动结算结果、遗物发来的规则事件。
- 处理规则：
  - [MUST] 充能状态用**百分比**存储（0–100），不存转动次数；关卡阶段初始为 0，进入下一阶段时保留百分比数值。
  - [MUST] 实际保底次数 `N_eff = max(1, N - D)`；D 是遗物减免的次数，**多个遗物相加**（买两个各减 1 次，就是减 2 次）。
  - [MUST] 每次普通转动结算后，充能增加 `100 / N_eff` 个百分点，上限 100；彩蛋转动本身不增加。
  - [MUST] 充能 `>= 100%` 时，**下一次**转动必定落到彩蛋卡并触发彩蛋（满格那一转不触发）。
  - [MUST] 轮盘上保留**多张**彩蛋卡（当前索引 9、21 共 2 张）；保底触发时从所有彩蛋卡里**等概率随机**选一张作为落点，其余格子不变。
  - [MUST NOT] 不得为了「只剩一张彩蛋卡」而删除或替换其它彩蛋格（此前把索引 21 换成小王的做法**作废**）。
  - [MUST] 触发彩蛋后同一帧内充能归 0。
  - [MUST] 基础次数 N 从 ScriptableObject 读取，暴露给执行策划调整（默认 4）；`N_eff` 最小为 1。
  - [MUST] 修改当前的彩蛋触发逻辑，把彩蛋卡的权重概率降为 0，只能通过保底触发。
  - [MUST] 遗物对充能的影响（减少次数、关闭保底、读取状态）一律通过 `struct` 事件，不允许遗物直接改充能字段。
  - [MUST] 保底关闭时，进度条 **直接隐藏**（`SetActive(false)`），不是置灰；重新启用时带着原百分比显示。
  - [MUST NOT] 不得修改彩蛋的类型、彩蛋效果的选择权重与 `CanTrigger` 判定。
  - [MAY] 触发时播放 0.4s 彩蛋触发 UI 动画。
- 输出：彩蛋选中图案、当前分数和总分数状态更新、充能百分比与状态事件。
- 状态变化：初始 充能=0% → 每次转动 +100/N_eff（clamp 100）→ 达到 100% 后下一次转动强制落到彩蛋 → 触发后充能=0%。
- 数值与公式：`N_eff = max(1, N - D)`；`progress += 100 / N_eff`；`progress = clamp(progress, 0, 100)`；
  满格条件 `progress >= 99.99f`；触发后 `progress = 0`；N 默认 4，D 默认 0（无遗物时 4 次转动充满）。


## 5. 详细流程

1. 初始状态：进入关卡，充能百分比 = 0%（跨关保留上一关的数值）。
2. 触发条件：普通转动结算后充能增加；`progress >= 100` 时标记「下次保底」。
3. 系统处理：下一次转动从所有彩蛋卡索引里随机选一个作为目标索引 → 走 `EasterEggManager.TryTriggerEasterEgg` 抽取彩蛋。
4. 结果反馈：进度条 UI 刷新、彩蛋动画播放【暂时搁置】、彩蛋逻辑触发、充能归 0 并广播事件。
5. 结束条件：游戏结束或回到主菜单。

## 6. 边界与异常情况

- 无效输入：彩蛋触发本身不会增加保底进度；转动动画未结束时的点击不产生新转动，不累加充能。
- 资源不足：转动券不足导致 `StartButton` 不可用，不产生转动，充能保持不变。
- 重复触发：`isSpinning` 或 `isEasterEggExecuting` 期间的点击被忽略，充能不会重复累加；同一帧内不会连续触发两次彩蛋。
- 中途退出或重进：退出关卡回主菜单后再开新局，按 `GamblingGround.Init()` 归零；同一关卡内进出面板不影响充能。
- 其他特殊情况：轮盘**没有**彩蛋卡时不强制落点、Console 告警并回退权重抽取；有**多张**彩蛋卡时按「随机选一张」处理；遗物通过事件关闭保底时，充能不再累加、也不强制落点，**进度条隐藏**（已积累的百分比保留）。

## 8. 数据与技术约束

- 输入数据：
  - `cardItems`（当前轮盘卡牌）与 `rewardData.runtimeCardType`；彩蛋卡用 `CardItem.CardType.彩蛋` 识别，对应资产 `Assets/Resources/Data/CardData/彩蛋.asset`（当前 `ChanceWeight: 25`）。
  - `Global.easterEggProgress`（**新增**，`BindableProperty<float>`）：充能**百分比** 0–100；跨关保留。
  - `Global.easterEggSpinsReduction`（**新增**，`BindableProperty<int>`）：遗物减免的转动次数 D，**多个遗物累加**，默认 0，新开局归零。
  - `Global.easterEggEnabled`（**新增**，`BindableProperty<bool>`）：保底开关，默认 `true`，新开局恢复。
  - `EasterEggConfig.RequiredSpins`（**新增** ScriptableObject，`Assets/Resources/Data/EasterEggConfig.asset`）：保底需求转动次数 N，默认 4；执行策划可改。
  - 一次转动的结算回调 `GamblingGround.OnSpinComplete(int selectedIndex)`。
  - `Global.currentLevelSpinCount`、`Global.level`：仅用于展示与统计，不参与保底判定。
- 输出数据：
  - 本次转动的强制目标索引（落点）；非保底时为 `GetWeightedRandomIndex()` 的结果。
  - 充能百分比 `progress`（0–100），供进度条 UI 实时读取。
  - 彩蛋触发结果：`EasterEggManager.TryTriggerEasterEgg(...)` 的返回值。
  - 分数变化：沿用彩蛋效果内部对 `Score`（总分）与 `CurrentLevelScore`（本关）的现有写入，不新增分数通道。
- 依赖系统：
  - `GamblingGround`：`StartSpin()` / `GetWeightedRandomIndex()` / `SpinToPosition()` / `OnSpinComplete()`。
  - `EasterEggManager.TryTriggerEasterEgg()`：按权重选择彩蛋效果，受 `isEnabled` 与 `EasterEggEffect.CanTrigger` 约束。
  - `EasterEggEffect` 子类（`FruitEasterEggEffect` / `GamblingEasterEggEffect`）与 `EasterEggEffectHelper`。
  - `CardItem` / `RewardData`（彩蛋卡资产）、`Global`（Architecture + BindableProperty）。
  - `UIGamePanel`（UIKit 面板）承载进度条 UI；改 prefab 后必须重建 AssetBundle。
  - **事件通道（遗物 ←→ 充能）**，全部用 `struct` 事件，禁止遗物直接改充能字段：
    - `EasterEggChargeChangedEvent { float Progress; int Level; bool Triggered; }` —— 充能变化/触发后由充能逻辑广播；UI、遗物、成就等只读监听。
    - `EasterEggChargeRuleEvent { int SpinsReductionDelta; bool Enabled; }` —— 遗物请求修改规则：`SpinsReductionDelta` 是**增量**（+1 = 少要 1 次转动，多个遗物自然累加），`Enabled = false` 关闭保底；由 `GamblingGround` 接收并写入 `Global`。
  - 事件命名与 `struct` 约定沿用现有 `BuyRelicSuccessEvent`；注册方必须 `UnRegisterWhenGameObjectDestroyed`。
- 必须保持的不变量：
  1. `N_eff = max(1, N - D)`；普通转动结算后 `progress += 100 / N_eff` 并 clamp 到 100，`0 ≤ progress ≤ 100`（float）。
     浮点累计要有容差：判定用 `progress >= 99.99f`（或第 N_eff 次增量后直接置 100），避免 `16.666…×6 = 99.999` 卡住不触发。
  2. `progress >= 99.99f` 时，**下一次**转动的目标索引必须是**随机选中的某张**彩蛋卡索引（多张时等概率）；命中彩蛋后同一帧内 `progress = 0`。
  3. 彩蛋转动本身不累加充能，即使彩蛋效果内部又触发了其他卡片的结算。
  4. 轮盘上必须**至少一张**彩蛋卡（当前 2 张：索引 9、21）；0 张时不得强制索引、不得崩溃——打 Warning 并回退普通权重抽取；多张时同权重等概率随机选一张，且不影响其它格子的权重与内容。
  5. 彩蛋卡 `runtimeChanceWeight` 必须为 0，且权重抽取要**显式跳过 0 权重卡**：现有实现用 `randomValue <= currentWeight`，当 `Random.Range` 返回 0 时会误命中排在前面的 0 权重卡，必须改判条件而不是只改数值。
  6. 彩蛋仍然只走 `EasterEggManager.TryTriggerEasterEgg` 这一条路径，不得新增直接调用 `EasterEggEffect.ExecuteEffect` 的旁路。
  7. 跨关保留的是**百分比数值本身**：`N_eff` 变化（遗物减次数）时只影响后续每次增量（`100 / N_eff_new`），不重算已有百分比。
  8. `D` 是**累加**的整数（多个遗物各减 1 次即 -2），`N_eff` 不得小于 1；遗物不能通过事件把 `N_eff` 降到 0 或负数。
  9. `easterEggEnabled == false` 时不累加、不强制落点、不广播触发事件，并**隐藏进度条**（`SetActive(false)`）；已积累百分比保留，重新启用后带原进度显示并继续使用。
  10. `isSpinning == true` 或 `isEasterEggExecuting == true` 期间不得累加充能，避免连点/彩蛋动画中重复计数。
  11. `GamblingGround.Init()` 新开局把 `progress`、`spinsReduction`、`enabled` 全部恢复默认（0 / 0 / true）。
  12. 分数仍走现有链路（`Score` / `CurrentLevelScore`），UI 文本只读显示，不在 UI 里改分数。
- 禁止修改的内容：
  - `EasterEggManager` 的彩蛋效果权重、随机选择逻辑与 `EasterEggEffect.CanTrigger` 判定。
  - 两个彩蛋效果（水果 / 赌博狂潮）的实现，以及它们对分数、加倍、按钮计数的操作。
  - `GetWeightedRandomIndex` 的权重算法本身（只允许在「保底命中」分支旁路，不允许改动算法）。
  - `RelicSystem.TriggerRelicEffect` 的调用点与遗物触发时机。
  - 抽奖券、下注倍率、`Global.levelScore` / `greedlevelScore` 的语义。
  - `CardItem.CardType` 枚举与彩蛋卡资产（唯一例外：`ChanceWeight` 置 0）。
  - 遗物直接读写 `Global.easterEggProgress`（只能发 `EasterEggChargeRuleEvent` / 收 `EasterEggChargeChangedEvent`）。

## 9. 验收标准

- [ ] 正常流程：每次转动后充能 +`100/N_eff` 个百分点；`>=100%` 后的下一次转动强制命中**随机一张**彩蛋卡并触发，触发后充能归 0
- [ ] 多张彩蛋：轮盘保留 2 张彩蛋卡，多次保底触发能落在两张卡上（不是固定同一张）
- [ ] 边界条件：转动中或彩蛋执行中点击不累加充能；`>=100%` 时不会在同一转内连续触发两次
- [ ] 异常数据：轮盘没有彩蛋卡时回退普通抽取并告警，不崩溃、不强制落点
- [ ] 事件链路：遗物用 `EasterEggChargeRuleEvent` 减少次数/关闭保底；`N_eff` 最小为 1；`EasterEggChargeChangedEvent` 能被监听；重开后规则恢复默认
- [ ] 表现：保底关闭时进度条隐藏（不是置灰），重新启用后带原进度显示
- [ ] 不影响关联系统：彩蛋效果、分数、押注倍率、下一关判定与改动前一致
- [ ] 通过相关测试：QA-001 ~ QA-013（见下表）
