        /// </summary>
        public static int PickIndex(float[] weights, float roll01)
        {
            if (weights == null || weights.Length == 0)
            {
                return 0;
            }

            float total = 0f;
            for (int i = 0; i < weights.Length; i++)
            {
                if (weights[i] > 0f)
                {
                    total += weights[i];
                }
            }

            if (total <= 0f)
            {
                return 0;

            if (float.IsNaN(roll) || roll < 0f) roll = 0f;

                }

# 代码变更记录（DescriptionOfChanges）

## 什么时候必须执行

**只要这一轮里你修改、新增或删除了代码文件，就必须在结束回复前跑一次记录脚本。**
"代码文件"指：`Assets/**/*.cs`、`*.asmdef`、`*.shader`、`*.hlsl`、`Tools/**/*.ps1`、`*.json`（配置类）。
文档（`*.md`）、美术资源、场景/预制体 YAML 不算代码；但如果这一轮同时改了代码和文档，按代码那次记录即可。

不要攒着以后补：**记录是改动的一部分**，和改代码同一次回答完成。

## 怎么跑

在仓库根目录执行（PowerShell 5.1 需要 `-ExecutionPolicy Bypass`）：

```powershell
powershell -ExecutionPolicy Bypass -File Tools\Agent\change-log.ps1 `
  -Summary "一句话说明改了什么" `
  -Detail "为什么改、影响哪些功能、怎么验证的（可多行）"
```

- 默认范围：**工作区相对 HEAD 的全部改动**（已暂存 + 未暂存 + 未跟踪），自动忽略 `DescriptionOfChanges/`、`Library/`、`Logs/`、`Builds/`。
- 只记某几个文件：加 `-Files Assets/Scripts/Relic/RelicSystem.cs,Assets/Scripts/Core/QualityWeights.cs`。
- 已经提交完了要补记：加 `-Commit <sha>`。
- 想把文档也带上：加 `-AllFiles`。

## 写什么

- **Summary**：动词开头的一句话，和 git 提交信息同风格（`新增遗物：紫色筹码翻倍`、`修复转动逻辑判断`）。它会变成文件名的一部分。
- **Detail**：至少写清「为什么改」和「怎么验证的」。这段是给人看的，不要复述 diff。
- **一次逻辑改动一条记录**：同一轮里改了三处但属于同一件事 → 跑一次、合并描述；确实是三件独立的事 → 跑三次，每次配 `-Files`。

## 脚本会产出什么

文件：`DescriptionOfChanges/<MM>/<yyyy-MM-dd>.md`（`MM` 是两位月份，如 `10`）。

**一天一个文件**：同一天的多次改动全部追加进同一个文件，用 `---` 分隔成 `## 变更 1`、`## 变更 2`……，
脚本会自己读出现有编号接着写，不需要你手动改。每条变更固定包含：

- 变更标题（`## 变更 N · HH:mm:ss (+09:00)`）；
- 摘要、范围、分支；
- 涉及脚本清单；
- 每个文件的**具体代码片段**：修改的文件给 unified diff，新增文件给前 60 行摘录，删除文件给原内容；
- 你的说明段落。

## 失败与边界

- 脚本退出码 `1` 且提示「没有检测到需要记录的代码改动」→ 说明这轮确实没动代码，忽略即可。
- 退出码 `1` 且提示找不到 git 仓库 → 你在错误的目录，回仓库根再跑；**不要**伪造记录文件。
- 不要在 `DescriptionOfChanges/` 里手写/改文件；只由脚本生成，避免格式漂移。
- 记录文件要跟着代码一起提交（同一次 commit），不要单独攒成"日志提交"。

    /// 关卡进度规则：死亡线 / 強欲线只统计「进入本关之后」获得的分数。
    /// 历史总分单独累计（后续可作为货币消耗），两者不能混用。
    ///
    /// 注意：needed 的数值仍由 <c>Global.levelScore</c> / <c>Global.greedlevelScore</c> 决定，
    /// 这里只负责「拿哪个分数去比」——要调难度改那两个值，不要改这里。
    /// </summary>
    public static class LevelScoreRule
    {
        /// <summary>
        /// 本关已获得的分数 = 当前总分 - 进入本关时的总分。
        /// 跨关不重置总分，所以必须靠 levelStartScore 做基线；基线缺失时返回 0 而不是负数。
        /// </summary>
        public static int LevelProgress(int totalScore, int levelStartScore)
        {
            int progress = totalScore - levelStartScore;
            return progress > 0 ? progress : 0;
        }

        /// <summary>本关进度是否达到某个门槛（死亡线 / 強欲线）。</summary>
        public static bool Reached(int totalScore, int levelStartScore, int required)
        {
            if (required <= 0)
            {
                return true;
            }

            return LevelProgress(totalScore, levelStartScore) >= required;
        }

        /// <summary>
        /// 进入新关卡时要把基线推到当前总分；返回新基线，便于调用方直接赋值。
        /// </summary>
        public static int BeginLevel(int totalScore)
        {
            return totalScore;
        }
    }
}

# QFramework 玩法开发约束

这个工程是 QFramework 架构：`Global : Architecture<Global>` 是唯一入口，System 注册在里面，全局状态是
`BindableProperty<T>`，UI 是 UIKit 面板。**核心玩法代码不得绕开这套结构**——出现 `FindObjectOfType`、
`new XxxSystem()`、static 状态、`Resources.Load`，就算功能能跑，也算不合规。

## 先认清四个角色

| 角色 | 本工程位置 | 写法 |
|---|---|---|
| Architecture | `Assets/Scripts/Global.cs` | `public class Global : Architecture<Global>`，`Init()` 里 `RegisterSystem<T>()` |
| System | `RelicSystem` / `EnchantmentSystem` | `AbstractSystem, IXxxSystem`；`OnInit()` 里初始化；用 `this.GetSystem<IXxxSystem>()` 取 |
| Model | 目前没有 | 需要存档/纯数据时新建 `AbstractModel`，`RegisterModel` + `GetModel<T>()` |
| Controller | `GamblingGround`、`UIGamePanel` 等 | `ViewController, IController` + `GetArchitecture() => Global.Interface` |

UI 面板：`UIPanel` + `partial` + `.Designer.cs`（生成文件，**不要手改**）；打开/关闭一律 `UIKit.OpenPanel<T>()` / `ClosePanel<T>()`。

## 三条线，别混

1. **状态线**：跨系统、跨关卡的数值 → `Global` 的 `BindableProperty`；只属于某个对象的临时状态 → 留在该对象里。
2. **通信线**：System 想通知 UI / 其他系统 → `struct` 事件（`this.SendEvent(new XxxEvent{...})`，UI 侧 `this.RegisterEvent<XxxEvent>(...)`）。**不要**在 System 里引用面板或 Controller 实例。
3. **资源线**：资产加载 → `ResLoader` / `ResKit`；面板 → UIKit；玩法代码不写 `Resources.Load`。
